# Security Policy

## Supported Versions

This project is actively maintained and security updates are provided for the following versions:

| Version | Supported          | Status |
| ------- | ------------------ | ------ |
| Latest  | :white_check_mark: | Active development |
| 1.x     | :white_check_mark: | Receiving updates |
| < 1.0   | :x:                | No longer supported |

## Reporting a Vulnerability

We take security seriously and appreciate your responsible disclosure of any vulnerabilities you discover.

### How to Report

**Please do not publicly disclose the vulnerability.** Instead:

1. **Email us directly** at suppa-r@github.com with the subject line "Security Vulnerability Report"
2. **Include the following details:**
   - Description of the vulnerability
   - Affected version(s)
   - Steps to reproduce (if applicable)
   - Potential impact
   - Any suggested fixes (if you have them)

### What to Expect

- **Initial Response:** We will acknowledge receipt of your report within 48 hours
- **Assessment:** We will assess and investigate the vulnerability within 5-7 business days
- **Updates:** You will receive regular updates on the status of your report
- **Resolution:** We will work to release a security patch as soon as possible
- **Disclosure:** We will coordinate with you on the timing of public disclosure

### Security Update Process

When a security vulnerability is confirmed:

1. We will create and test a fix
2. We will release a new version with the security patch
3. We will publish a security advisory
4. We will notify users through GitHub security advisories and release notes

## Security Best Practices for Users

- **Keep Updated:** Always use the latest version of this project
- **Review Dependencies:** Monitor dependency updates and security advisories
- **Report Issues:** Use the responsible disclosure process above for any security concerns
